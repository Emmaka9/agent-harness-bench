Merge-interval Calendar

Create `src/calendar.js` exporting two named ESM functions, `mergeIntervals(intervals, opts)` and `findFreeSlots(intervals, window, minDurationMs, opts)`. An interval is an object `{start, end, label?}` where `start` and `end` are epoch milliseconds (numbers) and `label` is an optional string; `window` is an object `{start, end}` in epoch milliseconds with `start <= end`; `minDurationMs` is a number of milliseconds. Node.js builtins only, no external packages. ESM. Neither function mutates its arguments, and both return fresh plain objects.

Options: both functions take a final `opts` object, which may be omitted. `opts.now` is optional and defaults to `Date.now`; when present it must be a function or undefined, otherwise a `TypeError` with message `"now must be a function or undefined"` is thrown. The results of both functions depend only on their inputs, never on the real clock. `findFreeSlots` additionally supports `opts.offsetMin`, optional, default 0: a number of minutes by which the window is shifted before any comparison — the effective window is `{start: window.start + offsetMin * 60000, end: window.end + offsetMin * 60000}`; when present it must be a finite number, otherwise a `TypeError` with message `"offsetMin must be a finite number"` is thrown. Option validation runs before interval validation (in `findFreeSlots`: `now`, then `offsetMin`, then the intervals).

Validation: each interval of `intervals` is checked in input order, and the first interval for which `start < end` is not true (reversed, equal, or otherwise non-comparable values) causes a `TypeError` with message `"invalid interval: start must be < end"`. Both functions validate identically.

`mergeIntervals` returns the intervals merged: it sorts them by `start` ascending (stably — equal starts keep their input order) and collapses any run of intervals in which each one starts at or before the previous one's end (so overlapping and exactly touching intervals merge). Each merged interval is a plain object with `start` (the smallest start in the run), `end` (the largest end in the run) and the label of the run's earliest-starting source interval — with equal starts, the one appearing first in the input — taken verbatim, including when it is undefined, in which case the returned object has no `label` property. No other properties are copied. `mergeIntervals([])` returns `[]`.

`findFreeSlots` merges first (with the same `opts`), clips each merged interval to the effective window (a clipped block that merely touches a window edge, and so has zero length, is dropped), and returns the uncovered sub-ranges of the effective window, ascending, as plain `{start, end}` objects with no `label` property. A returned slot satisfies `end - start >= minDurationMs`, so a gap of exactly `minDurationMs` is included and shorter gaps are never returned; zero-length gaps never appear. With no intersecting intervals the whole effective window is the single candidate slot.
