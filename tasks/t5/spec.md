Partial Update Endpoint

Extend a mini-repo: an in-memory document store (`src/store.js`), a request router (`src/router.js`), and create-time validation (`src/validate.js`). Add PATCH-style partial updates without changing existing behavior. Node.js builtins only, no external packages. ESM.

Existing exports must keep working exactly as now: `Store` (`create`, `get`, `list`, `delete`) and `NotFoundError` in `src/store.js`; `dispatch(req)` in `src/router.js`; `validateCreate(doc)` in `src/validate.js`.

1. `src/store.js` — add a `Store` method `update(id, patch)`: shallow-merge `patch` into the stored document for `id` and return the updated document. For each own enumerable string key `k` of `patch`: skip `k === "id"` (a patch never changes the id) and skip `patch[k] === undefined` (an undefined value neither overwrites an existing property nor adds a new one); otherwise set `next[k] = patch[k]`. `update` must not mutate the previously stored object: it builds a new object, stores that, and returns it, so references obtained earlier from `create`, `get`, or `list` still show pre-update content. Unknown `id`: `update` throws `NotFoundError`.

2. `src/validate.js` — additionally export `validators`, an object with exactly the keys `name`, `qty`, `tags`, each value a function `validator(value)` returning `true` or `false`. Rules: `name` is valid iff it is a string whose trimmed length is >= 1; `qty` is valid iff it is a number that is an integer >= 0 (so NaN, Infinity, 1.5, '3' are invalid); `tags` is valid iff it is an array whose every element is a string. Reimplement `validateCreate(doc)` on top of `validators` with exactly its current acceptance behavior: `{ok: true}` when valid; otherwise `{ok: false, errors}` mapping each invalid field name to the string `"invalid"`. A missing (undefined) `name` or `qty` is invalid; `tags` absent is valid; other fields are ignored.

3. `src/router.js` — add `"PATCH /items/:id"`; requests are `{method, path, body}`. The PATCH handler validates only the fields provided in `body` via `validators` (skip keys whose value is undefined and keys outside the schema). If any provided field fails its validator, respond `{status: 400, body: {error: 'invalid patch', fields}}` with `fields` mapping each invalid field name to `true`. If `body` is not a plain object (null, array, or primitive), respond `{status: 400, body: {error: 'invalid patch', fields: {}}}`. Validation happens before the store lookup: an invalid patch on an unknown id is 400, not 404. If the id does not exist and the patch was valid, respond `{status: 404, body: {error: 'not found'}}`; `dispatch` must catch `NotFoundError` raised by handlers and return that response instead of throwing. On success respond `{status: 200, body: <updated doc>}`; an empty patch `{}` is valid and returns the current doc. Routing stays as now: method and the literal `items` are case-sensitive; the collection `items` supports GET and POST only, the item `items/:id` supports GET, PATCH, and DELETE only; another method on a matching path is `{status: 405, body: {error: 'method not allowed'}}`, an unmatched path is `{status: 404, body: {error: 'not found'}}`.
